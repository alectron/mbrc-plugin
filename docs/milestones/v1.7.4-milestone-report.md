# Milestone Report: Features & Architectural Changes (v1.7.4 / v1.5.4)

**Target Versions**: Android `v1.7.4` (Build 136) | MusicBee Plugin `v1.5.4`  
**Date**: September 30, 2026  
**Status**: ✅ Released & Deployed to Device (Pixel 7 Pro) and Desktop Host

---

## 1. Executive Summary

The **v1.7.4 release (Android)** and companion **v1.5.4 release (Windows Plugin)** deliver the comprehensive **Generic Tag Architecture Refactor & Quality of Life (QoL) Enhancements**. 

Prior releases relied on bespoke, hardcoded pipelines for individual tag types (such as `Mood`, `Energy` 1-10 selectors, `Genre`, or custom 1..16 slot constraints). In this release, all tag types have been unified into a single, uniform metadata pipeline across the Rust core, C# plugin, wire protocol, Android database, and Jetpack Compose UI.

In addition, several major UX and workflow improvements requested during daily use have been designed and implemented:
1. **Configurable Tag Modalities & Custom Scales**: Any tag field can now be presented as Multi-Value Chips, Discrete Buttons, a Continuous/Stepped Slider, or Freeform Single-Value Text. Scales support continuous/stepped ranges (`min..max, step`) or arbitrary value lists (e.g. `16, 32, 64, 128`), with intuitive defaults (`0..10`, step 1).
2. **Settings Cog (⚙) Menu for Tag Entries**:
   - Replaced standalone row action buttons with an overflow Settings Cog menu.
   - Removed the standalone Delete button from the row so the enable switch sits flush with the right edge.
   - Ordered menu options:
     1. 🔒 **Lock / Unlock**
     2. ⬆ **Move Up**
     3. ⬇ **Move Down**
     4. 🎛 **Edit Modality & Scale**
     5. 🗑 **Delete Field**
3. **Collapsible "Available in MusicBee" Suggestions**:
   - Collapsed by default in the "Add Tag Field" dialog to avoid visual clutter.
   - Toggled via an interactive orange **`?`** button (`Color(0xFFFFA726)`).
   - Once expanded, chips are contained in a smooth vertically scrollable box (`heightIn(max = 140.dp)`) without clipping or truncation.
   - Dynamically discovers all standard MusicBee tags (`Artist`, `Album`, `Album Artist`, `Title` / `Track Title`, `Year`, `Mood`, `Occasion`, `BPM`, `Tempo`, `Genre`, `Grouping`, `Publisher`, `Composer`, `Comment`) and active custom slots (`Custom1`..`Custom16`).
4. **Tag Field Re-ordering & Playback Presentation**:
   - Custom tag fields can be re-ordered up and down in Settings, immediately dictating their display sequence on the Now Playing rating sheet.
5. **Lock / Read-Only Tag Protection**:
   - Marking a tag field locked visually greys it out on the playback rating sheet and disables editing, drag reordering, sliders, and dialogs.
6. **"Add Tag" Discovery Dialog (Star ★ vs Plus ✚)**:
   - A dual-mode discovery panel offering quick suggestions (8/12/16 chips) or full library tag exploration (e.g., all 388 genres) in a vertically scrolling view with an alphabetical A-Z / Z-A sort toggle.

## 2. Feature Additions & UX Adjustments

### 2.1 Configurable Single-Value Modalities & Custom Scales
* **Modality Selection**: In Settings (both when creating and editing tag fields), users can choose from four distinct input modalities:
  1. **Multi-Value Chips**: Comma- or semicolon-separated chips with drag-to-reorder support and quick "+ Add" dialog.
  2. **Discrete Buttons**: Clickable number buttons for discrete scales. Defaults to `0..10` (step 1). Alternatively supports arbitrary discrete values (e.g., `16, 32, 64, 128`).
  3. **Continuous Slider**: Draggable slider with live integer readout, default range `0..10` with step `1`.
  4. **Freeform Text**: Single-line text input with inline editing dialog.
* **On-Sheet Player Presentation**: The Now Playing bottom sheet dynamically chooses the appropriate composable based on the field's `TagDisplayType`, updating values optimistically in real-time.

### 2.2 Settings Cog (⚙) Menu & Flush Layout
* **Visual Cleanup**: Removed clutter from tag rows by replacing separate Lock and Delete buttons with a single Settings Cog (`Icons.Default.Settings`) icon button.
* **Flush Alignment**: Removing the standalone delete button ensures the toggle switch is the rightmost element in each row, aligning flush with other settings items.
* **Ordered Sub-Menu**:
  - `Lock / Unlock`: Toggles read-only protection on the field.
  - `Move Up`: Moves the field higher in priority (disabled when at top).
  - `Move Down`: Moves the field lower in priority (disabled when at bottom).
  - `Edit Modality & Scale`: Opens `EditCustomTagFieldDialog` to adjust modality and scale settings.
  - `Delete Field`: Confirms and removes the tag configuration.

### 2.3 Collapsible "Available in MusicBee" Suggestions
* **Expandable Drawer**: In `AddCustomTagFieldDialog`, the available tag fields section is collapsed by default.
* **Orange `?` Activity Indicator**: An orange badge button (`Color(0xFFFFA726)`) toggles the suggestions panel.
* **Scrollable Container**: Suggestions render inside a `Modifier.heightIn(max = 140.dp).verticalScroll()` box, avoiding layout overflows with extensive tag lists.
* **Full Taxonomy Access**: Supports both standard tags (`Artist`, `Album`, `Album Artist`, `Title`, `Year`, `Mood`, etc.) and custom slots (`Custom1`..`Custom16`).

### 2.4 Lock / Read-Only Tag Protection
* **Accidental Edit Guard**: Any tag field can be locked via the Settings Cog menu or the Edit dialog.
* **Read-Only Visuals**: Locked tags display a lock icon alongside their title, render chips and controls in muted disabled colors, and disable all interactive affordances (drag reordering, clear buttons, "+ Add", slider adjustment, and editing dialogs).

### 2.5 "Add Tag" Discovery Dialog (Star ★ vs Plus ✚)
* **Star (★) Mode**: Displays top suggestions (8/12/16 chips) sorted by relevance/frequency.
* **Plus (✚) Mode**: Expands container height (`max 260.dp`) with smooth scrolling to display the full library vocabulary (e.g. 388 genres) alongside a tag counter.
* **Alphabetical Sort Toggle**: Interactive sort button (`Icons.Filled.SortByAlpha`) toggles between A-Z and Z-A sorting.

## 3. Architectural & Protocol Changes

### 3.1 Dynamic Wire Protocol & Rust FFI (`mbrc-core`)
* **Dynamic Wire Dictionary**: Rust core `TrackDetails` now includes `pub tags: HashMap<String, String>`, serialized dynamically over JSON.
* **FFI Mapping**: Mapped across C# FFI as `Dictionary<string, string>`, completely replacing rigid struct fields with open-ended key-value pairs.
* **Available Tag Fields Protocol**: Introduced FFI query opcode 50 (`LibraryAvailableTagFields`) and command `availabletagfields`, returning all valid metadata tag fields and custom slots currently active in MusicBee.

### 3.2 Dynamic MetaDataType Resolution in Plugin (`mbrc-plugin`)
* **`GetMetaDataTypeFromTagName`**: Resolves arbitrary tag names dynamically against MusicBee's internal `MetaDataType` enum.
* **Standard Tags Extension**: Added explicit resolution for standard tags (`Artist`, `Album`, `AlbumArtist`, `Title`, `TrackTitle`, `Year`) in both query lookups and track details extraction.
* **Slot ID & Alias Resolution**: Custom tags can be addressed either by their slot identifier (`Custom1`..`Custom16`) or by the display name configured by the user inside MusicBee.
* **Panel Refresh**: Retained instant UI updates via `_api.MB_RefreshPanels()` on tag mutations.

### 3.3 Android Core Models & Serialization (`mbrc`)
* **`CustomTagFieldConfig`**:
  - Added `TagDisplayType` enum: `MULTI_CHIPS`, `DISCRETE_BUTTONS`, `SLIDER`, `TEXT`.
  - Added `NumericScaleConfig`: supports continuous/stepped ranges (`min`, `max`, `step`) or arbitrary value lists (e.g. `16, 32, 64, 128`), defaulting to `min = 0, max = 10, step = 1`.
  - Added `isLocked: Boolean` flag.
  - Backward-compatible serialization: parses legacy 3-part delimited strings (`name:multi:enabled`) seamlessly while supporting extended 9-part configuration format.
* **Dynamic Track Details**:
  - `NowPlayingDetailsPayload` deserializes dynamic `tags: Map<String, String>` into `TrackDetails`.
  - Case-insensitive, singular/plural resilient tag lookups in `TrackDetails.getTagValue(tag)` and `withTagValue(tag, value)`.

### 3.4 Android UI & State (`feature:settings` & `feature:playback`)
* **SettingsViewModel**:
  - Added `moveCustomTagField(fromIndex, toIndex)` persisting updated tag sequence to `SettingsStore`.
  - Added `updateCustomTagField(index, config)` allowing in-place edits to modalities and scale boundaries.
  - Added `loadAvailableTagFields()` querying MusicBee via opcode 50.
* **PlayerBottomSheet**:
  - Modality-driven tag rendering for Multi-chips, Discrete Buttons, Sliders, and Text.
  - Read-only locked styling and interaction suppression.
  - Star / Plus toggle and A-Z / Z-A sort in `AddTagValueDialog`.

# Milestone Report: Features & Architectural Changes (v1.7.1 & Post-1.7.1)

---

## 1. Executive Summary

The **v1.7.1 milestone and subsequent sprint** transformed the MusicBee Remote ecosystem from a playback control and standard library browser into a **two-way interactive metadata management system**. 

Previously, metadata flowed strictly downstream (MusicBee → Android) for standard fields (Artist, Album, Title, Genre, Rating). The system now supports **arbitrary custom tags** (e.g., `Energy`, `Instruments`, `Custom1..Custom16`), dynamic tag creation, fast synchronization of library-wide taxonomy values, and sub-millisecond local autocomplete—all while maintaining zero UI latency and strict thread safety.

## 2. Feature Additions (User-Facing Value)

### 2.1 Custom Metadata Tag Viewing & Editing (v1.7.1)
* **Configurable Tag Sheet**: The Now Playing player's rating sheet was expanded into a comprehensive metadata management panel.
* **Specialized Input Modalities**:
  * **Numeric / Selector Tags** (e.g. `Energy`): Quick interactive `1..10` filter chips plus clear button.
  * **Multi-Value Tags** (e.g. `Genre`, `Instruments`): Dynamic `FlowRow` chip clouds with individual removal and addition.
  * **Freeform Text Tags**: Inline editing dialogs for single-value custom tags.
* **Tag Configuration in Settings**: Users can define, enable/disable, and reorder custom tag fields matching their MusicBee setup.

### 2.2 Instant Optimistic UI (0ms Latency)
* **The Problem**: In initial prototypes, remote tag updates took 30–90 seconds to reflect on the phone because the client waited for the next polling cycle.
* **The Solution**: Implemented immediate local optimistic state mutation (`TrackDetails.withTagValue` and `RatingDialogViewModel._optimisticTags`). Tapping a chip or rating updates the UI instantly, while asynchronous network write requests process in the background.

### 2.3 Tag Verification & Visual System
* **Primary (Orange) Chips**: Indicate that a tag value exists and is confirmed in the MusicBee library cache.
* **Neutral Outline (Grey) Chips**: Indicate newly added, pending, or unconfirmed tags, giving immediate visual feedback on library consistency.

### 2.4 Fast Tag Metadata Re-Sync (Settings → Custom Tag Fields)
* **Selective, Targeted Sync**: Replaced slow full-library syncs (which transfer artwork and track indexes) with a lightweight, targeted metadata sync dedicated exclusively to active custom tag fields.
* **Atomic Database Flush**:
  * If no custom tag fields are enabled, clicking **Re-sync Tag Metadata** wipes the local cache to **0**.
  * When syncing configured tags, stale entries are cleanly replaced with fresh library values.
* **Live Database Status**: The Settings UI dynamically displays the live SQLite record count (e.g., `Fetch fresh metadata values from MusicBee (388 cached in database)` or `Database flushed (0 cached values)`).

### 2.5 Two-Tier Autocomplete & Suggestion Engine
* **Initial Quick Chips**: Opening the Add Tag dialog displays up to the user-configured limit (e.g., top 8) of recently used and top alphabetical suggestions.
* **Library-Wide Real-Time Search**: Typing even a single character in the dialog searches the **entire library vocabulary** (e.g., all 388 genres) in memory, making secondary and multi-value tags (`Cosmic`, `Sudan`, `Acholitronix`) instantly accessible.

### 2.6 Critical UX & Playback Stability Fixes
* **Timeline Playhead Sync**: Fixed an out-of-sync playback progress bar during track skips by resetting the playhead to 0 upon track change and forcing a fresh position query.
* **Bottom Sheet Flutter / Jitter Bug**: Eliminated sheet flutter near the top edge by locking `skipPartiallyExpanded = true` in Jetpack Compose modal bottom sheets.

## 3. Architectural & Flow Changes

### 3.1 End-to-End Bidirectional Protocol Architecture
* **Tag Write Protocol (`NowPlayingTagChange`)**:
  * *Android*: Added `TagChangeRequest` DTO and action mapping in [`UserActionUseCase.kt`](https://github.com/alectron/mbrc/blob/main/core/networking/src/main/kotlin/com/kelsos/mbrc/core/networking/protocol/usecases/UserActionUseCase.kt).
  * *Plugin*: Handled in `NowPlayingTagChange` ([`TrackDataProvider.cs`](https://github.com/alectron/mbrc-plugin/blob/main/packages/plugin/Providers/TrackDataProvider.cs)) → resolves friendly names to internal MusicBee slots (`Custom1..16`, `Genre`, etc.) → commits to file via `_api.Library_SetFileTag` → triggers immediate GUI repaint via `_api.MB_RefreshPanels()`.
* **Metadata Vocabulary Query Protocol (`browsetagvalues`)**:
  * *Protocol Command*: Added opcode 49 (`LibraryBrowseTagValues`) across the Rust FFI bridge (`mbrc-core`) and C# plugin host.
  * *Client Networking*: Added `LibraryApi.browseTagValues(tagNames)` returning structured `BrowseTagValuesResponse`.

### 3.2 Database Schema Evolution (Room Database v4 → v5)
* Added the `custom_tag_suggestions` table with a compound unique index on `(tag, value)`:
  * Table: `custom_tag_suggestions` (`id`, `tag`, `value`, `date_added`).
  * Index: `custom_tag_suggestions_tag_value_idx` on `[tag, value]` unique.
  * DAO: [`CustomTagSuggestionDao.kt`](https://github.com/alectron/mbrc/blob/main/core/data/src/main/kotlin/com/kelsos/mbrc/core/data/tags/CustomTagSuggestionDao.kt) providing case-insensitive lookups, reactive `countFlow()`, and `clearAll()`.
* Added `RecentTagsStore` utilizing an LRU JSON persistence model in `SettingsDataStore`.

### 3.3 Concurrency & Thread-Safety Overhaul
* **Issue Discovered**: Accessing Room DAO queries directly inside Jetpack Compose `remember { ... }` blocks triggered Android's `Cannot access database on the main thread` exception, which was silently swallowed by catch blocks, resulting in empty chips.
* **Architectural Fix**:
  * Decoupled UI rendering from database I/O.
  * Pre-aggregated suggestions and tag vocabularies asynchronously on `Dispatchers.IO` in [`RatingDialogViewModel.kt`](https://github.com/alectron/mbrc/blob/main/feature/playback/src/main/kotlin/com/kelsos/mbrc/feature/playback/player/RatingDialogViewModel.kt).
  * Exposed state via immutable `StateFlow<Map<String, List<String>>>` (`tagSuggestionsMap` and `allTagValuesMap`), allowing Compose UI to read instantly without blocking the UI thread.

### 3.4 Deep Multi-Value Metadata Extraction (MusicBee Storage Architecture)
* **The Root Limitation**: MusicBee's standard API query (`Library_QueryLookupTable("genre", ...)`) only exposes single primary genres (returning only 259 genres for the user's library).
* **Binary File Anatomy**: MusicBee stores multi-value tags inside `MusicBeeLibrary.mbl` records under internal field 83 (`Genres`), separated by null bytes (`\0`) or semicolons (`;`).
* **The Plugin Scanner**:
  * Implemented `ScanFilesForGenres` in `mbrc-plugin` ([`LibraryDataProvider.cs`](https://github.com/alectron/mbrc-plugin/blob/main/packages/plugin/Providers/LibraryDataProvider.cs)): iterates all library tracks, reading both `Plugin.MetaDataType.Genres` (field 143) and `Plugin.MetaDataType.Genre` (field 59).
  * Safely splits multi-value entries on `;` and `\0` while preserving composite style names (e.g. `Funk / Soul`), extracting the full **388 unique genres** across the entire 42,000+ track collection.

## 4. System Flow & Component Boundaries

```mermaid
sequenceDiagram
    autonumber
    actor User as User (Phone)
    participant UI as PlayerBottomSheet (Compose)
    participant VM as RatingDialogViewModel
    participant Room as SQLite (custom_tag_suggestions)
    participant Net as Network Layer (LibraryApi)
    participant Rust as Plugin Core (mbrc-core / Rust)
    participant CS as Plugin Host (LibraryDataProvider / C#)
    participant MB as MusicBee Engine & .mbl

    Note over User, UI: 1. Tag Synchronization Flow
    User->>UI: Tap "Re-sync Tag Metadata" in Settings
    UI->>Net: browseTagValues(["Genre", "Instruments", "Energy"])
    Net->>Rust: Opcode 49 (LibraryBrowseTagValues)
    Rust->>CS: BuildBrowseTagValues(tags)
    CS->>MB: ScanFilesForGenres() + QueryLookupValues()
    MB-->>CS: 388 Genres, 154 Instruments, 13 Energy
    CS-->>Rust: Packed TagValuesResult
    Rust-->>Net: JSON Response
    Net->>Room: suggestionDao.clearAll() + insertAll(entries)
    Room-->>VM: countFlow() emits updated count
    VM-->>UI: Subtitle updates: "Synced 388 metadata values..."

    Note over User, UI: 2. Interactive Editing & Autocomplete Flow
    User->>UI: Tap "+ Add" on Genre & types "Cos"
    UI->>VM: filter(text = "Cos") against in-memory allTagValuesMap
    VM-->>UI: Real-time matches: ["Cosmic"]
    User->>UI: Selects "Cosmic"
    UI->>VM: changeTag("Genre", "Reggae; Cosmic")
    VM->>UI: Instant 0ms Optimistic UI update (orange chip)
    VM->>Room: recentTagsStore.recordTagUsed("Genre", "Cosmic")
    VM->>Net: NowPlayingTagChange("Genre", "Reggae; Cosmic")
    Net->>CS: Library_SetFileTag() + MB_RefreshPanels()
    CS->>MB: Written to disk & GUI refreshed
```
